# Secure GF180MCU offline configuration

`configure-gf180` materializes the same externally anchored BiasWeave sizing
decision used by the SKY130 example into a GF180MCU 3.3 V common-source
characterization. The decision is bounded to 1 MiB and must match independent
decision, benchmark, comparison, topology, and topology-signature trust
anchors. Re-signing modified decision content therefore does not make it
trusted.

The supported PDK is the `gf180mcuC` variant from Ciel revision
`1689ac3f2dc763876eaf967227c7dfe831b031ae`. SimCairn pins the official Ciel
`common.tar.zst` and `gf180mcu_fd_pr.tar.zst` asset digests, installed
`nodeinfo.json`, and both selected ngspice files. Configuration performs no
network access and fails closed on a missing, symbolic, or mismatched file.
Absolute host paths never enter generated provenance or fingerprints.
The generated directory is therefore a portable local model cache: it can be
moved to another root and retains identical bytes and activity identities.

The generated product sweep contains 27 points:

- TT (`typical` in the foundry model), SS, and FF model libraries;
- 2.97, 3.30, and 3.63 V (nominal 3.3 V ±10%);
- -40, 27, and 125 °C.

The five batch-safe measurements are average output voltage, output
peak-to-peak voltage, 100 kHz transient voltage gain, average supply current,
and average power. Statistical global and mismatch switches are explicitly
disabled for a deterministic PVT reference. This is software-path validation,
not foundry sign-off or a circuit specification.

Generation refuses an existing destination and uses a sibling temporary
directory followed by an atomic rename. The copied Apache-2.0 PDK model bytes,
canonical decision, provenance, and corner wrappers are all manifest inputs.
See the example README for the exact mapping and command.
The real ngspice 42 run, measured ranges, and complete hash ledger are recorded
in `gf180-validation.md` and `../benchmarks/gf180-manifest.json`.
